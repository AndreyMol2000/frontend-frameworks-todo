# Мои задачи

Простое учебное ToDo-приложение для дисциплины «Фреймворки Frontend разработки», 6 семестр, преподаватель Золотов А. Л.

**Сайт:** https://andreymol2000.github.io/frontend-frameworks-todo/

**Исходники:** https://github.com/AndreyMol2000/frontend-frameworks-todo

[Успешные проверки и публикация в GitHub Actions](https://github.com/AndreyMol2000/frontend-frameworks-todo/actions/runs/43819631153).

Vue 3, Quasar, TypeScript (strict), Pinia, Vue Router, Axios, Zod. Без собственного CSS: оформление стандартными компонентами и классами Quasar.

## Запуск

Нужен Node.js 24 или новее.

```sh
npm ci
npm run dev
```

Открыть адрес, который покажет терминал (обычно http://127.0.0.1:9000).

Демо-вход: **student@example.com**, пароль **Demo1234!**. Можно создать вымышленный учебный аккаунт через кнопку «Регистрация».

## Возможности

- Добавление, изменение, выполнение и удаление задач.
- Поиск по названию, фильтры «Все», «Активные», «Готовые».
- Сохранение задач и настроек после обновления страницы.
- Учебные вход и регистрация; отдельные списки у пользователей.
- Настройки имени и светлой/тёмной темы.
- Защищённые страницы, хлебные крошки и 404.

Это mock-авторизация, а не защита для настоящего сервиса. Пароли и токены учебные; используйте только вымышленные данные. В браузерном демо данные остаются в localStorage этого браузера. Внешние API, настоящая аналитика и настоящий Sentry не подключены.

## Два режима API

По умолчанию включён автономный режим `browser`, поэтому опубликованное приложение работает на GitHub Pages без отдельного сервера. Axios adapter вызывает общий `mock/engine.ts`, имитирует 250 мс задержки и сохраняет данные в localStorage.

Практики 7–8 также реализованы с отдельным **json-server**. Для проверки:

1. Скопировать `.env.example` в `.env.local` (там выбран `VITE_API_MODE=server`).
2. В первом терминале выполнить `npm run mock`.
3. Во втором терминале выполнить `npm run dev`.
4. Открыть приложение. Запросы `/api` идут через Vite proxy на порт 3001.

Сервер использует `mock/db.local.json`, создаваемый из `mock/db.json`. Данные сохраняются между запусками. Задержка — 300 мс. CORS включён стандартным middleware json-server. Все маршруты проходят проверку учебного токена; пользователь может менять только свои задачи. Браузерный adapter и HTTP-сервер используют одну и ту же обработку запросов и валидацию.

Для возврата к автономному режиму установите `VITE_API_MODE=browser` в `.env.local` и перезапустите dev-сервер. Данные двух режимов независимы.

## Проверки

```sh
npm run lint
npm run typecheck
npm run test:coverage
npm run build:report
```

Тесты: Vitest + Vue Test Utils, без внешних API. Покрываются компоненты, composables, store, mock API, ошибки, валидация и обновление токена. Минимальный порог покрытия в конфигурации — 80%. HTML-отчёт: `coverage/index.html`.

При запущенном mock-сервере можно дополнительно выполнить `node scripts/check-mock.mjs` для проверки HTTP-контракта.

## Сборка и публикация

```sh
npm run build
npm run preview
```

Готовые файлы: `dist/spa`. Открывать через HTTP, не двойным кликом по `index.html`.

Workflow `.github/workflows/deploy.yml` запускает проверки и публикует сборку после push в `main`. В настройках репозитория выбрать **Settings → Pages → Source → GitHub Actions**. Workflow автоматически определяет путь публикации по имени репозитория.

Используется hash-маршрутизация (`/#/settings`), чтобы обновление любой страницы работало на GitHub Pages. Файл `_redirects` добавлен по заданию для хостингов, которые его поддерживают; GitHub Pages его не обрабатывает. Конфигурация кэша на стороне GitHub Pages задаётся самим хостингом.

`npm run build:report` создаёт `dist/bundle-report.json` с размерами и gzip-размерами ассетов. Используется анализ Vite, поскольку проект не собирается Webpack. Source maps в production выключены, страницы загружаются через dynamic import.
