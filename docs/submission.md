# Что нужно для сдачи

Подготовлен один простой проект по практикам 1–11: список задач на Vue 3, Quasar и TypeScript. Сайт-портфолио из старого репозитория к этому заданию не относится.

## Перед отправкой

1. Опубликовать исходники в отдельном GitHub-репозитории.
2. Включить GitHub Pages с источником GitHub Actions.
3. Дождаться успешного workflow и проверить опубликованную ссылку: вход, задачи, обновление страницы, настройки и 404.
4. Приложить ссылку на исходники и ссылку на работающий сайт.
5. Уточнить у преподавателя/куратора место сдачи. В проверенном модуле Нетологии формы итоговой не найдено. Требование видео или отдельного отчёта в прочитанных письменных практиках не указано.

## Короткая демонстрация

1. Войти: student@example.com / Demo1234!.
2. Добавить две задачи. Показать запрет пустого названия.
3. Выполнить одну задачу, переключить фильтры, найти задачу поиском.
4. Изменить название задачи и удалить другую.
5. Обновить страницу — задачи сохранятся.
6. В настройках изменить имя и тему, сохранить.
7. Выйти и открыть `/#/settings` — произойдёт переход ко входу.
8. Открыть несуществующий маршрут — появится 404.
9. При необходимости показать отдельный mock-сервер и результаты `npm run test:coverage`.

## Что понимать при защите

- Vue описывает компоненты и их реактивное поведение; Quasar даёт готовые элементы интерфейса.
- `ref` хранит изменяемое значение, `computed` рассчитывает фильтр и статистику.
- Компоненты получают данные через props и передают действия через emits. API вызывается в сервисах и store.
- Pinia хранит задачи, сессию и состояние интерфейса. Vue Router переключает страницы и проверяет доступ.
- TypeScript проверяет типы при разработке, Zod проверяет фактический пользовательский ввод.
- localStorage сохраняет демоданные только в текущем браузере.
- json-server имитирует backend локально; автономный режим нужен для статического GitHub Pages.

Если преподаватель сообщает иной формат итоговой или дополнительные требования, сопоставить их с проектом до отправки.
